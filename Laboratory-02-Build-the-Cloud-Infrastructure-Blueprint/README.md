# Cloud Infrastructure Blueprint

## Mission Overview

This laboratory activity focused on building a basic understanding of cloud infrastructure. Using the KillerCoda Playground and Linux terminal, I investigated a cloud-based Linux environment, identified its infrastructure components, researched major cloud providers, and created a simple cloud infrastructure diagram for a fictional company named **ARK**.

The activity also helped me practice documenting technical information using Markdown and managing my laboratory files through GitHub.

## Objectives

The objectives of this laboratory activity were to:

* Understand the major components of cloud infrastructure.
* Investigate hardware and software resources in a Linux environment.
* Identify compute, storage, and networking resources.
* Understand how cloud infrastructure components work together.
* Create a simple cloud infrastructure diagram.
* Compare cloud services from AWS, Microsoft Azure, and Google Cloud Platform.
* Create professional technical documentation using Markdown.
* Organize and maintain a Cloud Computing portfolio using GitHub.

## Cloud Infrastructure Components

| Component               | Description                                                              |
| ----------------------- | ------------------------------------------------------------------------ |
| **Compute Resource**    | Provides processing power for running applications and services.         |
| **Storage Resource**    | Stores files, data, and other information required by applications.      |
| **Network**             | Connects cloud resources and allows them to communicate with each other. |
| **User**                | Represents a person who accesses or uses the cloud system.               |
| **Internet Connection** | Provides connectivity between the user and cloud infrastructure.         |

For the simple infrastructure diagram, the fictional company **ARK** uses one compute resource, one storage resource, one network, one user, and one Internet connection.

## Linux Commands Executed

| Command               | Description                                                                |
| --------------------- | -------------------------------------------------------------------------- |
| `uname -a`            | Displays detailed information about the Linux kernel and operating system. |
| `cat /etc/os-release` | Displays information about the installed Linux distribution.               |
| `lscpu`               | Displays CPU model, architecture, and number of CPU cores.                 |
| `free -h`             | Displays the system's total, used, and available RAM.                      |
| `df -h`               | Displays disk usage and available storage space.                           |
| `lsblk`               | Lists available storage devices and partitions.                            |
| `mount`               | Displays mounted file systems.                                             |
| `hostname`            | Displays the hostname of the Linux system.                                 |
| `ip addr`             | Displays network interfaces and IP address information.                    |
| `pwd`                 | Displays the current working directory.                                    |
| `ls`                  | Lists files and folders in the current directory.                          |
| `cd`                  | Changes the current working directory.                                     |
| `mkdir`               | Creates a new directory.                                                   |
| `touch`               | Creates a new empty file.                                                  |
| `git status`          | Displays the current Git repository status.                                |
| `git add .`           | Stages files for a Git commit.                                             |
| `git commit`          | Saves staged changes to the Git repository.                                |
| `git push`            | Uploads committed changes to GitHub.                                       |
