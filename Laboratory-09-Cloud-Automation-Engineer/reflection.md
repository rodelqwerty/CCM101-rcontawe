# Mission Reflection — The Cloud Automation Engineer

Completing this laboratory helped me understand why automation is important in cloud computing. When managing hundreds of servers, performing repetitive tasks manually takes a lot of time and increases the possibility of human error. Bash scripts and Cron jobs allow administrators to automate regular tasks, such as backups, so that important operations can run consistently without requiring someone to execute every command manually.

However, automation also has risks. A script containing a destructive command or an incorrect file path could delete important information or damage configurations across many servers if deployed without proper testing. This is why scripts should be reviewed, tested in a safe environment, and monitored before being used on production systems. Automation should make work safer and more efficient, not spread mistakes more quickly.

Writing a Bash script was different from creating a Docker Compose YAML file in Laboratory 6. Bash scripts contain commands that execute operations in sequence, such as creating directories and compressing files. Docker Compose YAML describes application services, containers, networks, and other deployment settings. Both tools reduce manual work, but they solve different automation problems.

I started with Linux commands and basic cloud concepts, then progressed to Docker, object storage, application deployment, monitoring, security, and automation. These activities helped me understand that cloud computing involves more than simply running an application; it also requires managing resources, protecting systems, and maintaining reliable operations.
